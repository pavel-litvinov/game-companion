# Game Companion

Персональна система ігрових профілів, повідомлень, історії прогресу та знань із
джерелами. **Звичайний PostgreSQL і сервер працюють локально в Docker.**
Supabase, email-акаунт і платний хостинг не потрібні. Дані не заповнюються
вигаданими іграми, персонажами чи механіками.

## Запуск

Потрібні Docker Desktop, Node.js 22 або 24 та npm.

```sh
npm ci --ignore-scripts
npm run local:up
```

Команда генерує приватні локальні налаштування, запускає PostgreSQL, застосовує
міграції та збирає сервер. Ключ власника лежить у `.local/owner-key.txt` **відносно
кореня цього репозиторію**. Він потрібен для входу на сторінці Game Companion;
його не слід надсилати в чат або додавати в Git.

База не публікує порт на Mac чи в інтернет. Сервер доступний лише на
`127.0.0.1:3000`. Дані зберігаються в Docker-томі `game-companion_postgres_data`.
`npm run local:stop` зупиняє контейнери без видалення даних. Повторний запуск:
`npm run local:up`. Не видаляйте том бази, якщо хочете зберегти проходження.

## Доступ із ChatGPT

Cloudflare Tunnel надає серверу HTTPS-адресу. Встановіть `cloudflared` з офіційного
джерела, потім запустіть:

```sh
cloudflared tunnel --url http://localhost:3000 --no-autoupdate
```

Збережіть фактично отриману адресу як `PUBLIC_URL` у `.local/api.env` і виконайте
`npm run local:up`. У ChatGPT → Plugins → Add → Add custom MCP server вкажіть
`<отримана HTTPS-адреса>/mcp`, OAuth і Dynamic Client Registration. Сервер
автоматично публікує OAuth discovery, використовує PKCE S256 та перевіряє ресурс.
На сторінці Game Companion введіть ключ власника й надайте дозвіл плагіну.

Для нового встановлення можна також передати адресу одразу:

```sh
GC_PUBLIC_URL=https://your-actual-tunnel-host npm run local:up
```

Quick Tunnel безкоштовний, але його адреса змінюється при перезапуску; після зміни
потрібно оновити `PUBLIC_URL` і перепідключити плагін. Mac, Docker, сервер і тунель
мають працювати під час використання чату. [Докладніше](docs/local-and-chatgpt.md).

## Можливості MVP

- Ігри з платформою/версією та кілька окремих проходжень/персонажів.
- `submit_message`: надійно зберігає оригінал, потім обробляє його.
- Однозначні повні фрази `Мій рівень: 35.` або `I reached level 35.` оновлюють
  рівень автоматично. Решта залишається `needs_review`.
- Явно підтверджені рівень, персонаж, локація, інвентар, цілі та нотатки.
- Журнал до/після, ревізії, повторна доставка без дублювання та скасування останньої
  зміни через нову подію. Старі події не переписуються.
- Незмінні знімки джерел: HTTPS URL, версія гри, час отримання, текст і SHA-256.
  Твердження мають точні цитати з відповідного знімка.
- RLS, окрема обмежена роль БД для сервера, відсутність прямого запису в журнал,
  OAuth-токени з перевіркою власника/ресурсу/дозволу та відкликанням доступу.

## Перевірки

```sh
npm run check
npm test
npm run build
# Після запуску Docker; тестові дані будуть видалені.
npm run test:local
```

Тести перевіряють PostgreSQL/RLS, ізоляцію двох власників, повтори й конфлікти,
відновлення inbox, скасування, HTTP/MCP та повний OAuth-процес: вхід, згоду,
PKCE, refresh rotation, replay protection і відкликання. CI працює без секретів
на Node.js 22 і 24.
